Usage

Two inputs decide how it behaves. variant is how much UI the popup has; selectionMode is what a click picks. Without either it is the plain date picker every existing screen already uses, so old templates keep working unchanged.

selectionModeA click…ngModel value
defaultpicks the day and closes"2026-10-07T00:00:00"
range1st = start, 2nd = end, then closes["2026-10-01T00:00:00", "2026-10-07T23:59:59"]
presetpicks a whole period and closessame as range (preset id in selectionChange)
variant="default" variant="simple" variant="advanced"

Coming from <verben-date-picker> or <verben-simple-date-picker>

Both were folded into <app-date-picker>. Existing <app-date-picker> code needs no change at all.

Built-in quick choices

Week, month, quarter and year choices are calendar based: "Last 2 months" means the two complete months before this one. "Last N days" is rolling and includes today. The Periods tab shows a short list by default (at most four per tab) and the simple search lists all of them; [presets] sets your own. The last column shows what each means today (weeks starting Monday).
